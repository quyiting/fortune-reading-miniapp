# 多体系本地体验实现方案

用户已确认：四栏导航“首页 / 问事 / 命盘 / 记录”；本轮加入塔罗、梅花、八字、紫微；北京时间 UTC+8，不做真太阳时校正；出生资料仅在用户勾选后本机保存，可修改和删除；塔罗使用来源清晰的经典插画；AI 后续接入。

## 实现顺序与验收

1. 共用结果快照、备注、海报和导航：兼容旧记录，满20条仍先确认，回看不重新生成。
2. 塔罗：78张经典牌，单张/三张牌，不重复抽牌，保存牌序与正逆位；全部翻牌后才保存。图片及授权清单随代码提交，基础牌义为本项目编写。
3. 梅花：两数定上下卦，两数与北京时间时支序号定动爻；显示本、互、变卦、体用、公式和原始输入。
4. 共享出生表单：公历/农历、闰月、出生时间、排盘性别；日期严格验证。生日范围1900—2100；不自动校正历史夏令时，按用户输入的北京时间标准时处理并标注。
5. 八字：节气年/月柱，零点换日（子时日柱采用库 sect=2），时柱按输入时刻；未知时刻只展示三柱，不生成时柱、大运起运精确时间。已知时刻展示四柱、十神、五行、藏干和大运。
6. 紫微：固定并记录库排盘配置，未知出生时刻不能生成；展示十二宫、星曜、四化和基础说明。闰月规则与子时规则在页面注明。
7. 首页两入口、问事方式切换、命盘体系切换、记录类型下拉；小屏按钮边界检查及原生编译。

## 数据与构建

- 新增类型 tarot / meihua / bazi / ziwei，快照包含 schemaVersion、engineVersion、规则和生成时的完整显示数据。
- 出生资料与历史结果分开管理；取消资料保存会移除已保存的资料，不删除既有命盘记录。历史中保留当时输入；删除命盘记录可移除对应快照。
- JavaScript排盘库以固定版本构建为离线 CommonJS 文件；许可证保存在 licenses/，构建脚本可重现。牌面使用独立分包，避免主包膨胀。
- 本轮无模型调用、云端上传、支付和账户变更。

## 验证重点

牌序唯一性与重开一致、梅花公式与动爻、农历闰月和非法日期、节气/23点/零点边界、未知时刻、资料同意与删除、满额取消与保存失败、旧记录兼容、结果海报、320/375/430px按钮布局。
